## About

I learn systems by taking them apart. Read the source, reproduce the behaviour, break it on purpose, then rebuild it until nothing about it is mysterious. That habit is why I refuse to specialise too early: the problems worth solving tend to sit where AI, web engineering, and security overlap, and each one sharpens how I see the others.

I treat every project as an experiment against my own assumptions — ship it, measure it, find the part I got wrong, and fix that first.

## Approach

Curiosity opens the problem; discipline closes it. I want systems I can explain end to end, changes I can validate before they ship, and releases I can roll back without drama. Anything I cannot reason about, I do not consider finished.

The long game is a foundation deep enough that the next hard problem is a matter of engineering rather than luck.
